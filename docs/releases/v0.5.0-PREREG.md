# v0.5.0 source release verification — preregistration

Date: 2026-10-17. Task: LW-004. Commit this contract before implementing or
executing the producers and verifier. Human authority is recorded in LW-004.

## Identities and immutable inputs

- One exact LedgerWash commit per run. PR CI checks out the explicit head SHA,
  not GitHub's synthetic merge; push/tag CI checks out its exact commit.
- Nine GitHub-hosted cells: ubuntu-latest, windows-latest, macos-latest, each
  with Python 3.11, 3.12, 3.13. All run the unchanged acceptance suite and qualify.
- Five fixture families, built by committed deterministic builders with fixed
  dates and isolated Git configuration: main qualify, era-dead qualify, clean
  qualify, legitimate LF migration, self-consistent forged-parent migration.
  Every cell must produce identical Git epoch IDs for each family. Builders and
  fixture bytes are identified by the candidate commit; epoch IDs are outputs
  to reconcile, not values invented before execution.
- Invoke each fixture by the same single-component relative path and exact
  epoch SHA. Compare default/strict modes, seeds 1/17, raw captured stdout and
  `--out` file bytes. No post-hoc path, newline, encoding or JSON normalization.
  Each cell preserves 40 raw envelopes plus commands, exits, runtime, source,
  fixture pins and hashes. Fixtures live outside the product checkout.

The envelope emits target/ref metadata: equality requires identical invocation
inputs as well as identical epoch and engine. Stdout and files must both use
UTF-8 with LF. Static inspection found stdout currently fixes encoding but not
newline translation; implementation may align that serialization with the
existing file output. Preserve A1–A9 and all existing engine predicates.

## Predictions / acceptance

P1. All nine suites and qualify pass, with no skipped/failed/error tests.
P2. All five epoch identities match across cells. For each family/mode, every
seed/transport/cell has exactly identical raw bytes (40 outputs per cell).
P3. Main default and strict block, with the existing exact plant counts; the
era-dead corpus has its three planted rules and blocks in both modes. Clean
default passes with no findings; strict blocks its incomplete legacy receipts.
LF migration and forged-parent default both pass with no findings; strict
blocks their incomplete migration coverage. The forgery escape remains a limit.
P4. EC independently validates the expected repository, workflow path, exact
candidate SHA, run/attempt, completed-success run and all nine expected jobs.
Each unique expected artifact name includes run/attempt/cell, and its GitHub
artifact digest equals the original transported ZIP bytes. Require nonexpired
metadata, expected source/run binding, and creation during the matching job.
ZIP receipts must agree with all identities and contain exactly the prescribed
files. Missing, duplicate, mismatched or unverifiable inputs fail closed.
P5. EC creates isolated job-local environments using pinned uv bootstrap bytes,
runs `uv lock --check`, `uv sync --locked --extra dev` against the candidate's
unchanged lock, verifies installed distribution/engine versions 0.5.0/spec 5,
runs all tests and qualify through that installed environment, and performs a
local producer replay matching the hosted raw outputs. Source/lock stay clean.

The normal suite and replay must not rely on a product `PYTHONPATH` to disguise
a broken install. Pin build-tool versions for the isolated editable install and
record them; runtime/dev dependency versions and hashes remain those in uv.lock.
No wheel/sdist publication or PyPI release is part of this source release.

## Transport and evidence boundary

The operator downloads original ZIPs using existing read access and commits a
base64 transport bundle as immutable EC task evidence. This transport is not
treated as a witness. The token-free pool verifier reads the bundle and fetches
public GitHub primary metadata independently, verifying each service SHA256.
It stores the observed responses and exact ZIPs with its own receipt.

GitHub artifact metadata does not directly expose a producer job ID or attempt.
The binding uses the reviewed workflow, unique run/attempt/cell name, receipt
identity, attempt-specific jobs and creation interval; report that boundary
accurately. This does not add artifact/execution authenticity to LedgerWash's
scanner or authenticate any ledger supplied by a consumer.

Preserve all failure evidence and reconcile P1–P5 as held/not-held/incomplete.
Routine implementation defects may be corrected in scope with a new source/run;
new policy, venue or scope blockers stop release and return to the human.
Documentation-only closeout can follow the validated implementation; show the
exact diff, bind both SHAs, and require final candidate CI before publishing.
