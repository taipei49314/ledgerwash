## Retained failures and governance interruption

The first producer run [39038424178](https://github.com/taipei49314/ledgerwash/actions/runs/39038424178),
attempt 1 at `90eea1b`, had six successful Ubuntu/macOS cells and three incomplete
Windows producers. Windows stopped at the initial clean-source guard before
producing scan witnesses. That version did not retain dirty-path bytes, so the
exact dirty paths remain unknown. It did not establish nine-cell byte equality
or satisfy release acceptance. All nine original producer ZIPs and the three
failure JUnit ZIPs remain in immutable EC request
`00edbcec-412d-42b0-8629-757898237689`.

The diagnosed configuration risk was Windows checkout autocrlf conversion
followed by an isolated Git view. The repair pinned `core.autocrlf=false` during
checkout and retained initial/final status output and exit codes. The new
successful run used a new source SHA; it did not rewrite the failed attempt.

EC registry PR #190's first integrity run passed, but merge preflight refused
after evidence ledger writes advanced its render-sensitive base. The refusal
is preserved in EC request `61dcbc9c-6419-4a79-9bf6-56b3f201dac2`.
Nelson explicitly resumed T-553 and required a branch update, fresh fixed
base/head and no ledger writes during the new CI. Resumption is recorded in
`b7ddb8a0-454a-470f-b0eb-38a6a28b33d9`.

The new base `fde473cc743c6d82574222a9435ddaf0fa7f0208` and head
`cc4ed110328420c3b25e01dda78a57375afd3367` passed integrity run `39041471125`.
No ledger writes occurred through the verified merge `8b353f86f6c512b80a90f8971913c4175691f930`.
The merge contract and four receipts are in request
`8e9c2bda-2580-4107-a69a-a6483d6d5a84`. Registry acceptance was followed by
the separate product verifier above.

## Custody, final candidate and limits

Original producer ZIPs were transported unchanged in EC request
`b84438cc-2a95-463c-b389-20927ed753fd/producer-bundle.json`; bundle SHA256:
`d49dbf93b03bc7daf9c4a73ec1e605043cda048543917a8a3ea2ad8a91a69865`.
The operator transport was not treated as a witness. EC independently retrieved
GitHub primary metadata and checked service digests before consuming the bytes.

GitHub artifact metadata does not directly expose a producer job ID or attempt.
The binding combines the reviewed workflow, unique run/attempt/cell names,
receipt identity, attempt-specific job records and artifact creation intervals.

Documentation-only closeout follows the verified implementation as allowed by
the preregistration. The release notes will identify the final candidate, its CI,
and the exact Git comparison from `77efe40` to that SHA. No engine, fixture,
test, workflow, workload or lock changes are included in that closeout.

Across the five preregistered fixture epochs, all nine hosted cells produced
identical raw envelopes for the same portable target/ref, mode, seed and
transport. The installed EC Windows replay matched them. This is bounded
release evidence, not proof of determinism for every repository or of ledger
authenticity. Self-consistent forged-parent and backdated-committer cases remain
default-mode escapes; strict mode blocks their incomplete coverage. Continuity
does not establish trusted time or real execution. The earlier failed
[spec 5 prediction](../redteam/SPEC5-VALIDATION.md) and
[migration correction](../redteam/SPEC5-MIGRATION-VALIDATION.md) remain preserved.
